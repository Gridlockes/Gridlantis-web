What it is

Three ways to run something that isn't this computer

  • Virtual machines

    Point it at an ISO and you have a machine with its own disk, booting in its own window.

    • Any ISO — Linux, Windows, BSD, a rescue disc
    • Memory, cores and disk size per machine
    • BIOS or UEFI, for installers that insist
    • Hardware acceleration where your system has it

  • Containers

    Run a database, a web server or a build image in seconds, without installing any of it.

    • Create from any image — pulled for you if it's missing
    • Publish ports, mount folders, set environment
    • Start, stop, restart, inspect and read logs
    • Uses the Docker already on your computer

  • Device connections

    Reach another computer on your network and use its screen as if you were sitting at it.

    • VNC screens open inside Virtual Labs
    • RDP and SSH hand off to your system's own client
    • Scan the network to find what's already sharing
    • Share this computer's screen back the other way

How it works

It drives the tools you already have

Virtual Labs doesn't reinvent virtualisation — it puts a usable face on QEMU, Docker and VNC, which are the same tools professionals already run. That has consequences worth knowing about before you install anything.

Nothing is locked in

A machine created here is an ordinary qcow2 disk image. A container here is an ordinary container. Uninstall Virtual Labs and every one of them still works.

Nothing leaves your machine

There is no account, no cloud and no telemetry. Virtual machine screens and published container ports bind to 127.0.0.1 — reachable from your computer and nowhere else.

It tells you what's missing

A System tab lists every tool the app looked for, whether it found it, and the exact command to install it. No feature silently pretends to work.

One folder holds everything

Disks, ISOs, logs and settings live in a single folder you can open, back up or delete like any other. Virtual disks are sparse: a 40 GB disk costs what it actually uses.

Requirements

What each part needs from your computer

Every feature works on its own. Missing one tool disables one tab, not the app — and the System tab inside Virtual Labs shows this same table filled in for your actual machine.

ForYou needHow to install it
Virtual machines QEMU Arch: sudo pacman -S qemu-full
Debian/Ubuntu: sudo apt install qemu-system-x86 qemu-utils
macOS: brew install qemu · Windows: the QEMU installer
UEFI machines OVMF firmware Usually packaged as edk2-ovmf or ovmf. Needed by Windows 11 and other modern installers.
Full speed Hardware acceleration KVM on Linux, Hypervisor.framework on macOS, Windows Hypervisor Platform on Windows. Machines still boot without it, just slowly.
Containers Docker Engine Linux: sudo systemctl enable --now docker · macOS & Windows: Docker Desktop
Connecting out Nothing extra for VNC RDP uses FreeRDP or Remmina on Linux, and the built-in client on Windows and macOS.
Sharing this screen A screen server Linux: x11vnc, or wayvnc on Wayland. macOS and Windows switch this on in system settings instead.
